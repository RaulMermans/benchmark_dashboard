# Benchmark Dashboard Template

A generic, reusable React/Vite dashboard that converts structured benchmark data into an executive intelligence interface — with ranking views, market share, growth charts, forecast scenarios, event overlays, company profiles, and strategic signal cards.

---

## Public demo disclaimer

> **This repository uses synthetic/mock data only. It does not contain real company, client, competitor, or market data. The mock dataset exists purely to demonstrate the dashboard's interface, data model, and visualization logic.**
>
> All company names (`Focus Brand`, `Peer A–G`, `Market Average`) and all values (revenue, visits, share, growth) are randomly generated by a seeded script. No real benchmark, ranking, or business intelligence is embedded in this repository.

---

## What the project does

The dashboard ingests a normalized JSON payload and renders:

- **Benchmark ranking** — period-by-period ranked table and bar/pie visual
- **Market share** — revenue share and visit share over time per entity
- **Growth and traffic metrics** — YoY and MoM views with indexed growth race
- **Monetization gap** — revenue share vs visit share efficiency scatter
- **Forecast scenarios** — base, aggressive, and conservative scenario lines
- **Competitive map** — traffic × efficiency scatter plot with quadrant guides
- **Battle cards** — focus entity vs peers metric-by-metric comparison
- **Company profiles** — per-entity deep-dive with trend charts and KPIs
- **Event overlays** — calendar events (promotions, campaigns) highlighted on charts
- **Executive summary cards** — share movers, benchmark comparison strip, strategic signals
- **Presentation / slide capture mode** — minimal visual for slide exports
- **Data normalization layer** — tolerates varied field names, missing values, and multiple data types

## How the data works

The app loads data through `src/lib/api.js` with a two-step strategy:

1. If `VITE_BENCHMARK_API_URL` is set, it tries that endpoint first.
2. If the endpoint is absent or fails, it falls back to `public/data/benchmark-data.json`.

### Expected JSON shape

```json
{
  "ok": true,
  "meta": {
    "generated_at": "2026-01-01T00:00:00.000Z",
    "source": "Your connector name"
  },
  "data": {
    "interface": [],
    "events": [],
    "dictionary": []
  }
}
```

`data.interface` is the source of truth. `data.events` and `data.dictionary` are optional.

### Required fields in `data.interface[]`

| Field                   | Type          | Notes                                         |
| ----------------------- | ------------- | --------------------------------------------- |
| `date`                  | string        | `YYYY-MM-DD`                                  |
| `period_type`           | string        | `monthly`, `quarterly`, or `annual`           |
| `company_id`            | string        | Stable lowercase identifier                   |
| `display_name`          | string        | Label shown in UI                             |
| `type`                  | string        | `competitor` or `benchmark`                   |
| `market`                | string        | Market or filter label                        |
| `revenue`               | number / null | Optional metric                               |
| `visits`                | number / null | Optional metric                               |
| `market_share_revenue`  | number / null | Decimal, e.g. `0.18`                          |
| `market_share_visits`   | number / null | Decimal, e.g. `0.18`                          |
| `revenue_yoy_growth`    | number / null | Decimal, e.g. `0.12`                          |
| `visits_yoy_growth`     | number / null | Decimal, e.g. `0.12`                          |
| `data_type`             | string        | `estimated`, `actual`, or `forecast`          |
| `forecast_scenario`     | string        | Optional: `base_case`, `aggressive`, `conservative` |

Extra fields (ranks, MoM growth, share movement, indexed values, event signals, colors) are used when present. Field names can be adapted in the normalization layer (`src/lib/data.js`).

## Connecting your own data

### Option A — Static JSON file

Replace `public/data/benchmark-data.json` with your own export that matches the shape above. Run `pnpm build` to rebuild.

### Option B — Google Sheets

1. In your Google Sheet, build a tab with one row per company per period.
2. Publish the sheet data via a Google Apps Script web app, a Make/n8n scenario, or a serverless function that returns the expected JSON shape.
3. Set `VITE_BENCHMARK_API_URL` to the endpoint URL.

The Apps Script response should return:

```json
{ "ok": true, "meta": { ... }, "data": { "interface": [ ... ] } }
```

### Option C — Database or REST API

Create any endpoint that queries your database and returns the normalized benchmark payload. Works with any backend (Node, Python, Go, etc.) or BaaS (Supabase, PlanetScale, Neon, etc.).

### Option D — Warehouse or BI export

Schedule a warehouse query (BigQuery, Snowflake, Redshift, DuckDB) to write a JSON export to cloud storage or a serverless function. Point `VITE_BENCHMARK_API_URL` at the file or function URL.

## Environment variables

| Variable                 | Required | Description                                             |
| ------------------------ | -------- | ------------------------------------------------------- |
| `VITE_BENCHMARK_API_URL` | No       | Live JSON endpoint. If absent, the app uses local mock data. |

Create a `.env.local` file (never committed):

## Public-readiness audit

```bash

```

Checks the entire repository (excluding `node_modules`, `dist`, `.git`, `.tools`) for private brand names, private endpoint references, internal notes, forbidden paths, and any `.env.local` file. Fails with a clear list if anything is found.

This repository is designed for public GitHub hosting and portfolio presentation.

- The GitHub repository can be made public as-is.

- A Vercel deployment is optional. If you deploy it, use the demo mode (no `VITE_BENCHMARK_API_URL` set) so the deployment only serves synthetic data.
- Do not link a deployment that is connected to private or client data.
- If using a live demo link publicly, confirm it uses mock/synthetic data only.
